# Правила проекта 1С

## Что это за репозиторий
- `src/` — проект 1C:EDT (формат EDT: метаданные `.mdo`, формы `.form`, модули `.bsl`; рядом `.project` и `DT-INF/PROJECT.PMF`). Это не выгрузка из Конфигуратора.
- `tools/` — скрипты среды: `setup.sh`, `bsl-check.sh`, `rlm.py`.
- Изменения из `master` загружаются в **тестовую** базу скриптами `tools/*.bat` (рассчитаны на Конфигуратор — для EDT при необходимости адаптировать; в облаке загрузка в базу недоступна). В рабочую базу пользователь переносит изменения сам, средствами 1С.

- Конфигурация: Документооборот 8, редакция КОРП 2.1 (`ДокументооборотКОРП`).
- Платформа: 8.3.27 (runtime в `DT-INF/PROJECT.PMF`), режим совместимости: 8.3.14.

## Начало каждой сессии
1. `bash tools/setup.sh` — если инструменты ещё не установлены.
2. Коммитить сразу в `master`, отдельные `feature/`-ветки и pull request не нужны (если пользователь не попросил иначе). В облаке сессия может выдать свою ветку: работать в ней и после коммита отправлять в `master` — `git push origin HEAD:master` (fast-forward).

## Как искать в коде (экономия контекста)
- Не читать модули целиком. Сначала структура, потом нужная процедура:
  `~/.local/share/uv/tools/rlm-tools-bsl/bin/python tools/rlm.py src "<вопрос>" "<python с хелперами>" "<домены>"`
  Примеры хелперов: `find_module("Имя")`, `extract_procedures(path)`, `get_object_profile("Имя")`.
- Для простых поисков достаточно `grep -rn` по `src/`.

## Правила доработок
- Писать по стандартам 1С (its.1c.ru/db/v8std): русские идентификаторы, комментарии к экспортным методам, без запросов в цикле.
- Типовые объекты по возможности не менять — доработки через расширение или общие модули с префиксом компании.
- Изменённые места помечать комментарием `// expert1c <дата> <задача>` ... `// Конец expert1c` (формат согласован с пользователем; компания — `expert1c`; префикс для общих модулей — тоже `expert1c`, если пользователь не указал иное).
- Новые объекты метаданных (`.mdo`, `.form`) — только если без этого нельзя; сообщать пользователю, что их нужно открыть и проверить в EDT (валидность проверить в облаке нельзя). Существующие `.mdo`/`.form` править точечно, UUID не менять.

## Кодировка и формат файлов — важно
- Файлы проекта EDT: UTF-8 **без BOM**, переводы строк **CRLF** (так в репозитории сейчас). Сохранять так же; не перекодировать и не менять переводы строк (`.gitattributes`: `* -text`).
- Не переформатировать файлы целиком: diff должен содержать только смысловые изменения. При правке файла с CRLF вставлять строки тоже с CRLF.
- Служебные файлы `.project`, `DT-INF/PROJECT.PMF` не трогать без необходимости.

## Перед коммитом
1. `bash tools/bsl-check.sh --changed .` — ошибок уровня Error быть не должно.
2. Коммит с понятным описанием задачи, push в `master`, сообщить пользователю что изменено и какие объекты затронуты.
